# 日志详情链接授权改造计划

## 范围

- 技术栈：TanStack Router、React Query、Gin、现有 dashboard session。
- 目标：日志详情链接可携带 `session_id`，在没有浏览器登录状态时仍可直接加载该条日志详情。
- 授权边界：URL 中的 session ID 仅用于 `/api/log/detail/:detail_id`，不得成为全站 dashboard 登录凭据。

## 根因

详情页位于 `/_authenticated` 路由组，路由加载前要求 Zustand 同时存在用户和 access token；直接打开详情链接时首屏没有这两个状态，因此先跳转登录页。后端详情接口目前只接受 `Authorization`，也不会读取 URL 中的 session ID。

## 实施路径

1. 将详情页路由移出 `_authenticated` 路由组，保留普通已登录访问行为。
2. 详情 API 请求在存在 `session_id` 时把它作为查询参数传递。
3. 为详情 API 增加仅限该路由的 session-query 鉴权中间件：校验 session 生命周期、用户状态与日志归属；已有 Authorization 优先。
4. 新增中间件回归测试，覆盖有效 session、无效/过期 session、跨用户详情访问与普通 Authorization。

## 兼容与验证

- 无 `session_id` 的普通请求仍走现有 UserAuth。
- URL session ID 不注入 Zustand、不建立全站登录态，不扩大到其他 API。
- 使用 Bun 生成路由并执行前端类型检查/定向测试；执行 Go 中间件测试。

## 验证结果

- `go test ./middleware -count=1` 通过。
- `bun run typecheck` 通过。
- `bun run test -- src/features/usage-logs/lib/request-detail.test.ts` 通过（2 个测试）。
- `bun run build` 通过。
- 全量前端测试仍有 8 个既有失败，集中在 `redemption-codes`/`keys` 测试的 jsdom localStorage 环境与既有交互断言，本次定向测试未受影响。

## 详情列表交互优化

- 原因：列表单元格使用原生 `<a href>`，点击详情会触发浏览器整页导航。
- 改动：使用 TanStack Router `Link`，保留 detail ID 与 session 查询参数，让详情页通过 SPA 导航切换。
- 验证：日志详情链接测试 5/5、前端类型检查和生产构建通过。
